Release History
0.6.1 2026-08-02
  • Selection page renders large collections progressively in chunks with a load counter in the title bar — the page stays responsive instead of blocking while thousands of rows are inserted
  • Batch delete / prefix-based move run as background jobs with live progress in the dialog (polled every 400 ms); the batch buttons stay disabled until the list has finished rendering
  • Bucket dropdown refreshes automatically when opened — newly created buckets appear without reloading the page
  • New CLI mode --seed: deterministically fills an S3-compatible server with test data (options for object count, shard prefixes, size range, parallel uploads, --empty, --dry-run, --no-verify-ssl) — see the README
  • Easter egg: searching for osterei / easteregg / huevo de pascua triggers a small surprise
0.6.0 2026-08-01
  • Fixed move always reported as "skipped": the existence check was evaluated against the source object; the target key is now checked before copying — targets are never overwritten and skips are detected correctly
  • Unified move semantics — single move and batch move both take a target prefix (the object's folder is replaced, only the file name is kept); the dialog offers a dropdown of the shared prefixes from the current results
  • If a move copy succeeds but deleting the source fails (e.g. missing permission), a clear warning states that a duplicate may exist and must be cleaned up manually
  • Action history: origin/error columns removed from the table and from the API/download export
0.5.9 2026-08-01
  • Move and delete S3 objects — per row in the results and as batch operations (delete / prefix-based move) in the selection
  • Batch move replaces the object's own folder with the target prefix: data/shard-00/test1/file.odt with target archive/ becomes archive/file.odt — objects keep only their file name, files from subfolders are moved flat into the target prefix
  • Move is copy + delete: the source is only removed after a successful copy; existing targets are skipped (never overwritten) and recorded in the action history — when moving many objects at once, make sure target keys are unique, otherwise objects are skipped
  • Action history (/history) — every move/delete is recorded as an audit log in ~/.bucketeer/actions/actions.jsonl, reviewable and downloadable as JSON
  • After move/delete the row is removed from the cached results; collected items are cleaned from the selection

Template Syntax

segment1/{functionName(ref, arg1, arg2)}/segment3/
data/{everyNth(key, 0, 2)}/{key}/
logs/{date(yyyy/MM/dd, -1d)}/errors/
reports/{upper(everyNth(key, 0, 2))}/{key}/
Segments
References

Reference Meaning
key
bucket
p1, p2, … pN

Function Chaining

{upper(everyNth(key, 0, 2))} → everyNth result in uppercase
{lower(left(key, 5))} → first 5 chars in lowercase
{left(everyNth(key, 0, 2), 4)} → everyNth result, first 4 chars
{upper(everyNth(p3, 0, 2))} → everyNth on literal segment 3, uppercased
{repeat(p4)} → copies the value of segment 4 directly
{upper(repeat(p2))} → segment 2 value in uppercase
Wildcard

Key: ABCDE* → lists all objects whose key starts with ABCDE
